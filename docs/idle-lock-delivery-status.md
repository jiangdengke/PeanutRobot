# 锁屏配送界面

## 效果

点击“立即出发”且配送任务创建成功后，屏幕立即锁定，挡住主界面的所有操作。锁屏壁纸照常显示，配送提示叠在屏幕底部约 30% 的区域（现场熊猫壁纸的嘴巴下方，不遮挡五官），该区域有从透明到深色的渐变遮罩，保证在任意壁纸上都看得清。

| 阶段 | 提示 |
| --- | --- |
| 前往点位 | 卡通字体的超大“配送中...”（白字紫色描边）；下方显示“正在前往 第 N/M 个点位 · 点位名”和流动进度条 |
| 到点等待取餐 | “请取餐...”（白字紫色描边，与“配送中”色调一致）；呼吸高亮的紫底白字白边“请从 X 号仓取餐”；下方显示“第 N/M 个点位 · 点位名” |

提示文字在底部区域居中，不带图标；标题 80sp、仓号 36sp、点位信息 24sp。标题末尾的点每 500 毫秒按 `.` → `..` → `...` 循环，标题宽度固定，文字不会左右抖动；内容超过底部区域时自动等比缩小，缩放按两种状态中较高的一种计算，切换状态时标题大小不变。

文字使用站酷快乐体（ZCOOL KuaiLe，SIL Open Font License 1.1），字体文件为 `app/src/main/res/font/zcool_kuaile.ttf`，许可证随 APK 放在 `assets/licenses/ZCOOL_KuaiLe_OFL.txt`。字体约 1.5MB；字体加载失败时回退为系统粗体。

## 显示时机

| 情况 | 配送界面 |
| --- | --- |
| 点击“立即出发”，配送任务创建成功 | 立即锁屏并在屏幕底部显示 |
| 前往点位 | 显示“配送中...” |
| 到点等待取餐 | 显示“请取餐...”和仓号 |
| 取餐完成或超时，前往下一个点位 | 切回“配送中...” |
| 最后一个点位取餐完成或超时，开始召回 | 隐藏，只剩锁屏壁纸 |
| 停止、上游路线抢占、导航错误等导致任务取消 | 隐藏，只剩锁屏壁纸 |
| 机器人还没开始行驶就出发失败（停止充电失败或超时、路线准备超时等） | 隐藏并自动解锁，方便重试 |
| 急停按下期间 | 隐藏，只剩锁屏壁纸；松开后恢复 |
| 上游下发路线、巡仓、回充、召回 | 不显示 |

## 解锁

与原锁屏一致：2.5 秒内连续点击屏幕左上角 5 次，再输入进入密码。配送提示不拦截这个手势。解锁后配送任务继续进行；60 秒无操作会再次锁屏，配送仍在进行时重新显示配送提示。

## 急停

App 从急停按钮的 SDK 回调（`BUTTON_STATUS`，数据为 `{"data":{"info":true}}`）读取急停状态，`info` 为 `true` 表示急停按下。

- 急停只隐藏配送提示，不取消配送任务，不改变导航，也不自动解锁。
- 每次急停状态变化都写入运行日志，模块为 `ESTOP`，记录 `emergencyOpen` 的值。

> v1.0.13-beta.1 曾依赖 SDK 的 `EVENT_EMERGENCY_STATUS_CHANGED` 事件，但该事件不会触发：Peanut SDK 的 `subscribe` 只把每个主题的数据回调给第一个订阅者，App 先订阅了急停按钮主题，SDK 内部的运行时模块收不到数据。

## 不受影响的行为

- 60 秒自动锁屏、隐藏解锁方式和进入密码不变。
- 屏保图片、旋转角度和显示模式不变。
- 配送导航、到位上报、取餐等待和召回流程不变。

## 现场验证

1. 绑定点位后点击“立即出发”，确认立即锁屏，屏幕底部出现卡通字体的“配送中...”且不遮挡壁纸主体，主界面无法点击，点在跳动、进度条在流动。
2. 到点等待取餐时，确认切换为“请取餐...”和紫色仓号提示，仓号与绑定一致；取餐后前往下一个点位，确认切回“配送中...”。
3. 最后一个点位完成后，确认配送提示消失，只剩锁屏壁纸。
4. 配送途中按下急停，确认配送提示消失、锁屏保留；松开后确认恢复。运行日志中应有 `ESTOP` 记录：按下时 `emergencyOpen=true`，松开时为 `false`。
5. 充电中点击“立即出发”并让停止充电超时（或模拟路线准备失败），确认自动解锁并提示重试。
6. 在锁屏左上角连点 5 次并输入进入密码，确认可以解锁。
7. 换几张不同的屏保壁纸，确认提示文字都清晰可读。
