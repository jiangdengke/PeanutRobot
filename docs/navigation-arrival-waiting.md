# 导航到位等待方案

> 状态：方案已确认，本轮未实现。

## 后续业务流程

1. 屏幕选择多个点位并立即出发后，机器人每到达一个点位，先通过 HTTP 向上游上报到位。
2. 到位上报后，机器人在当前点位原地等待五分钟。
3. 中间点等待满五分钟，且未收到上游有效的 `/robot_task/send_point` 请求时，继续前往原路线的下一个点位。
4. 最后一个点等待满五分钟，且未收到上游有效请求时，调用现有 9098 召回能力。
5. 等待期间收到上游有效的 `/robot_task/send_point` 请求时，立即取消当前倒计时，执行新任务，并用新任务替换原路线尚未完成的点位。

“有效请求”沿用 `/robot_task/send_point` 现有业务校验结果；无效请求不取消等待计时，也不替换剩余路线。

## 待上游确认

- 到位 HTTP 接口的完整 URL。
- 请求方法、请求字段及字段含义。
- 成功与失败响应格式。
- 上报失败时的重试或降级规则。

## 本轮实现边界

本轮不修改导航到位处理，不发送到位 HTTP，不启动五分钟计时，不实现中间点超时续航、最后一点超时召回，也不改变 `/robot_task/send_point` 对现有路线的处理方式。该文档仅作为后续开发和联调依据。
