# 应用内运行日志

## 用途

诊断日志继续在后台采集机器人业务关键时间线，但主界面右侧的“运行日志”入口当前暂时隐藏，待现场需要排查时再恢复显示。该能力重点排查以下现场问题：

- 点击“立即出发”后机器人运行几秒停止；
- 回充完成后再次选择相同点位，机器人不移动；
- 导航准备完成但未进入运行状态；
- 导航、回充、上游任务或取餐等待发生意外抢占。

该功能只记录和展示事件，不提供停止、重试、回充或导航控制，不改变现有机器人任务。

## 现场使用

当前版本默认不显示“运行日志”按钮。需要现场排查时，先恢复主界面入口，再按以下步骤查看或导出；入口隐藏期间，内存快照和 App 私有轮转文件仍按原规则持续记录。

1. 保持 App 正常运行并复现问题。
2. 点击右侧“运行日志”。
3. 弹窗会显示打开时的日志快照，并自动滚动到最新记录。
4. 问题继续发生时，点击“刷新”读取最新内存快照。
5. 点击“复制全部”，将当前保留范围内的全部诊断日志复制到系统剪贴板；或点击“导出文件”，将点击瞬间的快照保存为 UTF-8 TXT。
6. 导出成功后按提示到系统 `Download/PeanutRobotLogs/` 查找 `robot-runtime-yyyyMMdd-HHmmss-SSS.txt`，再将复制内容或文件发送给开发人员分析。

“清空”只清除内存和 App 私有目录中的诊断记录，不会取消或改变当前机器人任务。清空前会显示二次确认。

导出操作为空时只显示提示，不创建空文件。开始写盘后“导出文件”按钮会暂时禁用，完成或失败后恢复；若旧版系统的权限弹窗出现，即使此时关闭运行日志弹窗，授权后仍会导出最初点击时已经保留的快照。

## 手动导出路径和系统版本

| 系统版本 | 写入方式 | 权限行为 | 现场路径 |
|---|---|---|---|
| Android 10 / API 29 及以上 | `MediaStore.Downloads`，先标记 `IS_PENDING`，完整写入后发布 | 不申请存储权限 | `Download/PeanutRobotLogs/<文件名>.txt` |
| Android 9 / API 28 及以下 | 系统公开 Downloads 目录中的普通文件 | 只在点击“导出文件”且尚未授权时申请 `WRITE_EXTERNAL_STORAGE` | 外部存储绝对路径下的 `Download/PeanutRobotLogs/<文件名>.txt` |

权限拒绝、系统下载目录不可用、队列繁忙或文件写入失败都会显示提示，不会改动机器人任务。MediaStore 写入失败会删除 pending 条目，旧版文件写入失败会尽量删除半成品。

## 日志格式和范围

每条记录为单行文本：

```text
时间 | 级别 | 模块 | 消息
```

示例：

```text
2026-08-06 17:20:01.123 | INFO | NAV | 接受 STATE_RUNNING task=12, position=0
```

第一版覆盖：

- `LIFECYCLE`：主界面创建、前台、后台和销毁；
- `SDK`：PeanutSDK 初始化结果；
- `NAV`：任务创建、路线准备、SDK 状态、`STATE_RUNNING`、`STATE_DESTINATION`、到位停止、错误、超时和任务失效；
- `CHARGER`：回充动作、充电状态、功率事件和错误；
- `DELIVERY`：屏幕仓位任务创建、取消和完成；
- `ARRIVAL` / `PICKUP`：到位等待、取餐回调、五分钟超时和路线推进；
- `HTTP`：上游任务路径、`nav_arrive` 请求及结果；
- `WAREHOUSE`：回充、巡仓和召回 WebSocket 请求及确认结果。

日志不读取完整系统 Logcat，也不记录 SDK secret、锁屏密码或认证信息。点位 ID、点位名称、仓位、任务状态和局域网接口路径会用于故障定位。

复制和导出共享同一个内容边界：只使用操作发生时的 `DiagnosticLogRecorder.snapshot()`。导出器不会重新读取私有轮转文件，不会追加系统 Logcat、文件头、说明文字或尾换行；TXT 字节就是该快照字符串的 UTF-8 编码。点击后继续产生的新日志不进入已经提交的导出文件。

## 保存和容量

- 文件位于 App 私有 `files/diagnostic_logs/` 目录，不需要外部存储权限；
- App 启动时会加载之前保留的日志，因此重启后仍可查看；
- 文件写入由独立单线程队列异步执行，导航回调和主线程不直接写磁盘；
- 待写队列最多保留 512 个操作，写入异常缓慢时丢弃额外文件操作而不阻塞机器人回调；内存快照仍保留最新记录；
- 单个文件上限为 256 KiB，最多保留 4 个文件，文件总量约 1 MiB；
- 界面内存快照上限为 256 KiB；
- 超过容量时自动淘汰最旧记录，单条异常大记录也会截断到文件上限内；
- 文件读取、写入或清理失败只输出到 Logcat，不向机器人业务调用方抛出异常。
- 诊断目录已从 Android 云备份和设备迁移中排除，避免运维数据离开当前设备。
- 手动导出使用独立的有界单线程队列，最多等待 4 个导出任务；队列饱和会立即提示而不会阻塞主线程，也不会挤占私有轮转日志的记录队列。

## 常见时间线判断

### SDK 主动报告到位后停止

```text
接受 STATE_RUNNING
接受 STATE_DESTINATION
到位后发送 readyGo(false)
开始等待取餐
```

若停止前出现该顺序，说明 App 接受了 SDK 到位回调并进入屏幕取餐等待。

### 回充或仓库任务抢占

```text
收到上游请求 path=/robot_task/go_to_charge
屏幕仓位任务取消
执行上游回充任务
充电状态 status=...
```

若停止前出现该顺序，应继续核对回充任务来源和 Charger 状态。

### 路线准备后未运行

```text
路线准备完成并发送 readyGo(true)
```

之后长时间没有“接受 STATE_RUNNING”，说明问题发生在 SDK 准备完成到实际运行之间。当前版本只记录该现象，不修改机器人控制逻辑。
