# 三仓位点位绑定

## 功能范围

Android 横屏主界面固定展示“仓位 1”“仓位 2”“仓位 3”。仓位绑定仅在应用内存中维护，应用重启后不保留。

## 绑定交互

1. 先点击“仓位 1”“仓位 2”或“仓位 3”，将其设为当前编辑仓位；当前仓位使用紫色高亮，切换仓位时只有最新选择保持高亮。
2. 再点击上方点位列表中的未占用点位。空仓位会直接完成绑定，已绑定仓位会直接替换为新点位。
3. 点击已绑定仓位后，再点击该仓位当前绑定的点位，会解除绑定并保留该空仓位的选中状态，方便继续选择替代点位。
4. 未选择仓位时点击点位不会修改绑定，界面会临时提示先选择仓位。
5. 如果点位已被其他仓位占用，界面会提示对应仓位，不移动或重复绑定该点位。
6. 屏幕配送任务进行期间，点位和仓位仅供查看，点击不会修改当前绑定。

未绑定仓位只显示仓位编号和加号；已绑定仓位显示仓位编号、点位名称和勾选图标。点位列表只高亮实际已经绑定的点位，不常驻展示操作教学文案。

## 约束

- 一个仓位最多绑定一个点位。
- 一个点位只能属于一个仓位。
- 最多绑定三个不同点位。
- 成功获取非空点位快照后，仓位绑定按点位 ID 更新为最新对象；新快照中不存在的点位会被清除。
- 临时未获取到点位、解析失败或返回空列表时，保留上一次成功点位快照、当前仓位绑定和编辑仓位，并继续现有重试流程。

## 导航顺序

只有至少一个仓位已绑定有效点位时，才能点击“立即出发”。没有绑定时，界面提示先绑定点位到仓位；出发时会清除当前编辑仓位的高亮，不影响已经完成的绑定。

导航路线按点位首次成功绑定到仓位的先后顺序生成，不按仓位编号排序。直接替换已绑定仓位的点位会保留该仓位原有的路线位置；先解除绑定再重新绑定时，新点位会按新的绑定时间追加到路线末尾。导航继续复用现有 `prepareNav` 流程。

## 充电控制交接

- 充电控制已经停止时，“立即出发”继续直接进入现有路线准备流程。
- 正在充电或上游回充任务仍处于活动状态时，App 会先立即停止上一条 SDK 导航，再保留本次出发的路线快照、发送停止充电指令并最多等待十秒；等待期间不会提前准备或强制启动导航。
- 每次充电交接都有单调递增的代次标识。只有属于当前代次的充电状态 `1` 或 `6` 会继续该路线，重复状态回调不会重复启动，已取消交接的迟到状态、错误或超时也不能影响后续交接。
- 充电模块未就绪、停止指令异常、模块错误或等待超时时，App 会取消本次屏幕配送、恢复“立即出发”并提示重试。手动任务、有效上游任务抢占或 Activity 销毁也会清除待出发路线，迟到的充电回调不能再启动导航。
- 上游 `/robot_task/send_point` 的停止充电和完整路线准备行为保持不变。

## 配送进度界面

左栏顶部可在“点位选择”和“配送进度”之间切换。点击“立即出发”并成功创建屏幕仓位任务后，界面会自动切换到配送进度。

配送进度使用出发时的路线快照，逐项展示点位名称、绑定仓位和当前状态。后续刷新机器人点位不会改变本次配送快照。状态包括：

- `等待配送`：尚未开始前往的后续点位。
- `正在前往`：当前导航目标。
- `等待取餐`：已经到达，旁边显示五分钟剩余倒计时。
- `已完成取餐`：收到有效 pickup 通知后结束等待。
- `等待超时`：五分钟内未收到 pickup，按现有流程继续下一点或召回。
- `配送已取消`：手动任务或有效上游任务抢占了尚未完成的点位。

屏幕仓位任务进行期间仍可切换两个左栏页面查看信息，但点位和仓位绑定为只读；任务完成或取消后恢复编辑。最后一个点位结束并开始召回后，配送结果继续保留，直到下一次屏幕仓位任务创建新快照。

## 本轮不包含

- 仓位绑定持久化。
- 开仓控制或出发确认弹窗。
- 仓位绑定信息上传。

仓位任务的到位 HTTP 上报、取餐回调和五分钟等待流程见 [导航到位上报与取餐等待](navigation-arrival-waiting.md)。
