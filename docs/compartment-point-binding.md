# 三仓位点位绑定

## 功能范围

Android 横屏主界面固定展示“仓位 1”“仓位 2”“仓位 3”。仓位绑定仅在应用内存中维护，应用重启后不保留。

## 绑定交互

1. 点击上方点位列表中的未绑定点位，将其设为待绑定点位。
2. 再点击下方任一空仓位，将待绑定点位绑定到该仓位。
3. 再次点击当前待绑定点位会取消待绑定状态；点击另一个未绑定点位会切换待绑定点位。
4. 点击已绑定点位不会解除绑定。界面会提示通过对应仓位清空，并恢复该点位的选中状态。
5. 没有待绑定点位时，点击已占用仓位会清空该仓位。
6. 有待绑定点位时，点击已占用仓位只提示先清空，不覆盖原绑定，待绑定点位保持不变。

点位列表会同时高亮已绑定点位和当前待绑定点位，仓位区域会显示待绑定提示、仓位绑定的点位名称以及当前可执行操作。

## 约束

- 一个仓位最多绑定一个点位。
- 一个点位只能属于一个仓位。
- 最多绑定三个不同点位。
- 三个仓位都已占用时，不能再选择第四个待绑定点位。
- 成功获取非空点位快照后，仓位和待绑定状态按点位 ID 更新为最新对象；新快照中不存在的点位会被清除。
- 临时未获取到点位、解析失败或返回空列表时，保留上一次成功点位快照以及当前仓位和待绑定状态，并继续现有重试流程。

## 导航顺序

只有至少一个仓位已绑定有效点位，并且当前没有待绑定点位时，才能点击“立即出发”。没有绑定时，界面提示先绑定点位到仓位；仍有待绑定点位时，界面提示先完成绑定或取消选择，避免该点位被静默忽略。

导航路线按点位成功绑定到仓位的先后顺序生成，不按仓位编号排序。清空仓位会从路线中删除对应点位；重新绑定后，该点位按新的绑定时间追加到路线末尾。导航继续复用现有 `prepareNav` 流程。

## 配送进度界面

左栏顶部可在“点位选择”和“配送进度”之间切换。点击“立即出发”并成功创建屏幕仓位任务后，界面会自动切换到配送进度。

配送进度使用出发时的路线快照，逐项展示点位名称、绑定仓位和当前状态。后续刷新机器人点位不会改变本次配送快照。状态包括：

- `等待配送`：尚未开始前往的后续点位。
- `正在前往`：当前导航目标。
- `等待取餐`：已经到达，旁边显示五分钟剩余倒计时。
- `已完成取餐`：收到有效 pickup 通知后结束等待。
- `等待超时`：五分钟内未收到 pickup，按现有流程继续下一点或召回。
- `配送已取消`：手动任务或有效上游任务抢占了尚未完成的点位。

屏幕仓位任务进行期间仍可切换两个左栏页面查看信息，但点位和仓位绑定为只读；任务完成或取消后恢复编辑。最后一个点位结束并开始召回后，配送结果继续保留，直到下一次屏幕仓位任务创建新快照。

## 本轮不包含

- 仓位绑定持久化。
- 开仓控制或出发确认弹窗。
- 仓位绑定信息上传。

仓位任务的到位 HTTP 上报、取餐回调和五分钟等待流程见 [导航到位上报与取餐等待](navigation-arrival-waiting.md)。
