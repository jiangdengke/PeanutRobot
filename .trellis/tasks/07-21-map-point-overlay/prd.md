# 地图点位标注与联动

## Goal

让主界面中间地图尽量铺满可用区域，并在地图上增加与机器人点位对应的标注层。用户点击左侧点位时，地图能够突出显示对应区域；点位位置、显示名称和机器人点位映射可调整。

## What I already know

- 当前主界面是左侧点位、中间地图、右侧操作的横屏三栏布局。
- 中间地图当前由 `FrameLayout` 包含一个 `ImageView`，使用 `fitCenter` 显示 `root_map.jpg`，外层有 `8dp` padding。
- 当前地图图片尺寸为 `1202 x 1026`，宽高比约为 `1.17`；目标机器人实际中间区域可能更宽，因此 `fitCenter` 会产生左右留白。
- 左侧点位数据包含稳定的机器人点位 `id`、`name`、楼层及机器人地图坐标信息。
- 当前点位点击流程服务于“先选仓位，再选点位”的绑定交互；地图联动不能破坏仓位绑定、配送只读和路线顺序逻辑。
- 地图上层可以增加透明标注层，不需要改变现有三栏结构。

## Assumptions (temporary)

- 地图标注代表业务区域，不直接替代或修改 Peanut SDK 的真实导航坐标。
- 标注位置使用相对地图宽高的比例坐标，而不是固定屏幕像素，以适配不同横屏尺寸。
- 映射以机器人点位 ID 为主键，显示名称可以独立配置，避免机器人点位重名或改名后匹配错误。
- 地图铺满与标注坐标必须使用同一套缩放、裁切和偏移计算，避免图标错位。

## Open Questions

- 无。当前 MVP 范围已确认，等待进入实施阶段。

## Requirements (evolving)

- 中间地图移除内部白边并使用等比例铺满，允许裁掉少量顶部或底部内容，不使用拉伸变形。
- 在地图图片上叠加独立标注层，标注不会被写死到 JPG 图片内容中。
- 每个标注至少包含机器人点位 ID、比例坐标、显示名称和启用状态。
- 提供 App 内隐藏编辑模式，可选择机器人点位、在地图上新增或拖动标注、修改显示名称、删除标注并保存到本机。
- 正常模式禁止拖动或修改标注，避免配送操作时误改配置。
- 编辑过程提供保存和取消，取消时不覆盖上一次有效配置。
- 长按中间地图约 3 秒并验证现有锁屏密码后进入编辑模式，不在右侧增加新的常驻入口。
- 屏幕配送、App 本地导航任务和上游回充任务在各自可靠生命周期内禁止进入地图编辑模式；巡仓/回充/召回仅在 `9098` 请求发送和等待确认期间禁止进入，长按入口和密码确认均重新检查统一任务状态。
- 编辑模式下“立即出发、刷新点位、回充、巡仓、召回”不得执行；结构完整且输入有效的上游点位或回充任务保持抢占优先级，并在启动前丢弃未保存编辑工作副本。无效上游任务只记录日志并忽略，不得抢占或丢弃编辑。
- 地图配置仅在 MMKV 明确返回写入成功后替换已保存状态并退出编辑；写入失败时保留工作副本、当前选择和编辑工具栏。
- 点击左侧已配置点位时，地图显示明确的选中反馈。
- 正常模式显示全部已配置点位的小圆点；当前点位使用放大的紫色定位图标并显示名称。
- 编辑模式为全部标注显示名称，超长地图标签可省略但 Spinner 保留完整名称，方便识别、拖动和调整映射。
- 地图当前聚焦点与仓位绑定状态分离；点击左侧点位可更新地图聚焦，但原有仓位绑定校验和路线修改规则保持不变。
- 未选择仓位时点击左侧点位只聚焦地图，不显示“请先选择仓位”且不修改配送路线。
- 已选择仓位时点击左侧点位同时更新地图聚焦，并继续执行原有绑定、替换、解绑和重复占用校验。
- 点击没有地图配置的点位不阻断仓位绑定，可使用临时提示说明该点位尚未配置地图位置。
- 未配置映射的机器人点位仍可用于仓位绑定和配送，不因缺少地图标注而被拦截。
- 地图标注不得改变机器人导航坐标、仓位绑定和配送路线逻辑。
- 本地配置包含地图版本；地图资源变化时不直接套用不兼容的旧坐标。
- 点位已从机器人列表删除、配置内容损坏或字段无效时，忽略无效标注并保持导航和配送可用。
- 地图铺满与标注坐标使用同一套缩放、裁切和偏移计算；触摸越界时限制到 View 边缘对应的当前可见原图区域，避免写入被裁切区域。
- MVP 加载配置时直接忽略 disabled、空、坐标无效和重复 ID 标注，后续映射查找也只考虑启用且坐标有效的标注。
- 所有机器人点位已映射时，“新建标注”状态禁用点位和名称输入并明确提示；地图标签在顶部空间不足时下移、纵向不越界，超长名称省略显示。

## Acceptance Criteria (evolving)

- [ ] 地图在目标横屏中等比例铺满且没有明显白边，关键区域不被不可接受地裁掉。
- [ ] 标注在不同横屏尺寸下仍落在同一业务区域。
- [ ] 点击左侧已映射点位后，地图能突出显示正确标注。
- [ ] 正常模式中未选点位只显示小圆点，当前点位显示放大图标和名称，不出现大面积标签遮挡。
- [ ] 点击未映射点位时不崩溃、不影响原有仓位绑定，并给出合理的无标注状态。
- [ ] 未选择仓位时点击点位只更新地图聚焦，不出现绑定错误提示，也不会加入配送路线。
- [ ] 已选择仓位时地图联动与原有绑定、替换和解绑行为同时正常工作。
- [ ] 点位显示名称和位置可以通过最终选定的配置方式调整。
- [ ] 编辑模式可新增、拖动、改名、重新关联和删除点位，保存后重启 App 仍然有效。
- [ ] 取消编辑后保留进入编辑模式前的有效配置。
- [ ] 普通点击地图不会进入编辑模式，长按约 3 秒且密码正确时才可进入。
- [ ] 密码错误或配送进行中不会进入编辑模式，也不会改变已保存配置。
- [ ] 配送期间的只读规则和现有路线行为保持不变。
- [ ] 地图版本不匹配、点位不存在或本地配置损坏时，App 不崩溃且原有导航和配送仍可使用。
- [x] 长按入口和密码确认使用同一任务忙碌判断，覆盖屏幕配送、App 本地导航、巡仓/回充/召回请求发送及等待确认阶段，以及上游回充任务。
- [x] 编辑模式拦截右侧五个任务入口；有效上游点位和回充任务会先丢弃未保存编辑再按原优先级执行。
- [x] MMKV 返回 false 或抛异常时不替换已保存配置、不退出编辑，只有返回 true 才提示保存成功。
- [x] `centerCrop` 触摸边界限制在 View 当前可见原图区域，覆盖上下裁切、左右裁切、越界和非中心点往返测试。
- [x] 纯 Java 配置清洗覆盖版本不匹配、null、NaN/Infinity、越界、disabled 和重复 ID，disabled 不再形成隐藏占用。
- [ ] 全部点位已映射时新建状态不显示陈旧点位且不可误操作；标注改名后 Spinner 及时显示完整新名称；地图标签具备顶部不足下移、纵向限制和超长名称省略逻辑。
- [x] `/robot_task/go_to_charge` 在进入 UI 线程和抢占编辑前完成完整结构校验；只有正整数充电桩 ID 且充电模块可用时才启动，解析器覆盖无效输入且不向调用方抛异常。
- [x] 上游 `send_point` 到达最后一点后先保留完成回传数据，再结束本地导航活动状态；回传 WebSocket 不可用时仍清理本地状态。
- [x] Activity 销毁时结束待确认仓库 WebSocket、取消并关闭该 Activity 自有 OkHttp 资源，销毁后的仓库任务 UI Runnable 不再访问 binding。

## Feasible Approaches

### Approach A: 随包配置文件

- 在 App 资源中保存点位 ID、比例坐标和显示名称。
- 修改点位需要开发者调整配置并重新发布 APK。
- 实现最简单、风险最低，适合点位很少且变化不频繁。

### Approach B: App 内隐藏编辑模式（已选择）

- 正常模式只负责显示和联动；通过受控入口进入编辑模式。
- 编辑模式可选择机器人点位、在地图上拖动标注、修改显示名称并保存到本地。
- 坐标和映射可现场调整，无需每次重新发版；实现成本高于随包配置，但更符合实际部署调试场景。

## Confirmed Decisions

- 使用 App 内隐藏编辑模式维护地图点位，不依赖每次重新发版，也暂不接入后台远程配置。
- 点位配置保存在机器人本机，采用地图比例坐标，并以机器人点位 ID 作为映射主键。
- 编辑能力包括新增、拖动、修改显示名称、重新关联、删除、保存和取消。
- 编辑入口为长按中间地图约 3 秒并验证现有锁屏密码；机器人任务忙碌时禁止进入。
- `9098` 对巡仓、回充和召回只提供“已入队”确认，当前仓库及 vendor SDK 没有可证明对应三类外部任务的权威完成信号；MVP 的 `warehouseTaskPending` 互斥只覆盖请求发送和等待确认期间，不延伸到外部任务整个执行周期。
- 正常模式显示全部已配置点位的小圆点，当前聚焦点放大并显示名称；编辑模式显示全部名称，地图空间不足时省略但 Spinner 保留完整名称。
- 地图聚焦状态独立于仓位绑定状态，地图联动不改变原有配送路线。
- 地图采用等比例铺满模式并移除容器内部白边，接受少量顶部/底部裁切，不接受拉伸变形。
- 未选择仓位时点击左侧点位只聚焦地图；已选择仓位时同时聚焦地图并执行原有绑定流程。
- MVP 只实现地图铺满、App 内点位编辑和左侧点击联动，不加入地图反向选择、配送状态或配置导入导出。
- MVP 保留地图版本、无效点位和损坏配置保护。

### Approach C: 后台远程配置

- 点位映射由服务端下发，多台机器人可统一维护。
- 适合多门店、多地图，但需要新增接口、版本管理和离线策略，当前阶段成本最高。

## Definition of Done

- 明确地图铺满策略、标注显示规则和配置入口。
- 实现选定 MVP，并完成目标横屏上的位置与点击验收。
- 完成静态检查、单元测试及 Debug 构建。
- 同步正式使用文档和 `progress.md`。

## Out of Scope (temporary)

- 不修改 Peanut SDK 导航坐标或地图协议。
- 不根据机器人实时位置自动绘制运动轨迹。
- MVP 不实现点击地图标注后反向定位左侧点位。
- MVP 不在地图上展示“正在前往”“等待取餐”等配送状态。
- MVP 不实现点位配置导入、导出或跨设备迁移。
- MVP 不实现服务端跨设备点位配置。
- MVP 不新增无法可靠解锁的 `warehouseTaskActive`，也不使用固定超时或未知 SDK code 猜测巡仓、回充和召回的执行完成时间。

## Technical Notes

- 主要涉及 `activity_main.xml` 的中间地图容器、`MainActivity` 的点位点击状态和新增地图标注视图/配置存储。
- 使用等比例铺满时，标注坐标换算必须考虑图片裁切偏移；不能直接把比例坐标乘以整个 View 尺寸。
- 若使用 `fitXY`，坐标换算简单但地图会变形，不建议作为默认方案。
- 本地编辑模式可复用项目现有 MMKV 存储，但配置需要考虑地图图片变化后的失效或迁移。
