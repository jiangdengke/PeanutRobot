# 记录到位等待方案并增加三仓位点位绑定

## Goal

为三仓送餐机器人增加仓位与送餐点的明确绑定，限制一次最多选择三个点位，并且只有至少一个仓位已绑定有效点位时才允许立即出发。同时记录后续“逐点到位上报、等待五分钟、继续下一点或召回”的业务方案，本轮暂不实现到位等待和 HTTP 上报。

## What I already know

- 机器人有三个放餐仓位。
- 一次任务最多选择三个点位。
- 一个仓位最多绑定一个点位。
- 可以同时使用多个仓位和多个点位。
- 只有把点位绑定到仓位后才能立即出发。
- 当前界面左侧上半区是全部点位，下半区是 `selectedPointList` 已选点位列表。
- 当前立即出发直接按 `selectedPointList` 顺序生成导航路线，没有仓位模型。
- 当前点位选择按点位 ID 去重。
- 当前横屏中间地图和右侧操作区保持不变。

## Recorded Follow-up: Arrival Waiting Flow

- 屏幕选择多个点位并立即出发后，每到一个点都先通过 HTTP 向上游上报到位。
- 每个点到位后原地等待五分钟。
- 中间点等待五分钟未收到上游有效 `/robot_task/send_point` 请求时，继续前往原路线的下一个点。
- 最后一个点等待五分钟未收到上游有效请求时，调用现有上游召回接口。
- 等待期间收到上游有效新点位请求时，取消当前倒计时并执行新任务，原路线剩余点位不再继续。
- 到位 HTTP 接口完整 URL、请求字段和响应格式仍待上游确认。
- 上述流程属于后续任务，本轮不修改导航、HTTP 上报、等待计时或召回逻辑。

## Assumptions (temporary)

- 仓位绑定只在内存中维护，不做跨重启保存。
- 清空某个仓位后，对应点位恢复为可选择状态。

## Decisions

- 采用“先点击点位，再点击目标仓位”的两步绑定交互。
- 点位在绑定到仓位前只作为待绑定选择，不进入导航路线。
- 点击已绑定仓位可清空该仓位，之后可以重新绑定。
- 同一个点位只能绑定到一个仓位，不允许跨仓位重复绑定。
- 三个仓位使用“仓位 1”“仓位 2”“仓位 3”作为界面名称。
- 已占用仓位不能直接覆盖，必须先清空后再绑定新点位。
- 没有待绑定点位时，点击已占用仓位会清空该仓位。
- 多仓位任务按点位绑定先后生成导航路线，与仓位编号无关。
- 本轮保持最小范围，不增加绑定持久化、开仓控制或出发确认弹窗。

## Open Questions

- 无。

## Requirements (evolving)

- 主界面展示三个固定仓位。
- 一个仓位只能对应一个点位。
- 一个点位只能对应一个仓位。
- 一次最多绑定三个点位。
- 支持只使用一个、两个或三个仓位。
- 用户先选择一个点位，再点击仓位完成绑定。
- 未绑定任何仓位时，点击立即出发必须提示用户先绑定仓位。
- 已绑定仓位时，立即出发使用仓位绑定的点位生成路线。
- 待绑定点位必须在界面中有明确提示。
- 仍有待绑定点位时禁止立即出发，避免该点位被静默忽略。
- 已占用仓位不能被待绑定点位直接覆盖。
- 临时未获取到点位、解析失败或返回空列表时保留现有点位与仓位状态，仅在成功取得非空新快照后进行绑定对账。
- 保留现有点位刷新、地图、巡仓、回充、召回和锁屏行为。

## Acceptance Criteria (evolving)

- [ ] 界面始终显示三个仓位及各自绑定状态。
- [ ] 点位数量达到三个后不能继续新增绑定。
- [ ] 单个仓位不会同时保留两个点位。
- [ ] 同一个点位不能同时绑定到两个仓位。
- [ ] 多仓位路线按点位绑定先后生成。
- [ ] 未绑定仓位时不能开始屏幕导航，并显示明确提示。
- [ ] 存在待绑定点位时不能开始屏幕导航，并提示完成绑定或取消选择。
- [ ] 已绑定一个或多个仓位时可开始导航。
- [ ] 清空仓位后，点位选择状态与仓位显示保持一致。
- [ ] 点位刷新后，不存在的已绑定点位会从仓位中清除。
- [ ] 临时空点位刷新不会清空仓位、路线或待绑定点位。
- [ ] `:app:assembleDebug` 构建通过。

## Definition of Done

- 交互和重复点位规则经用户确认。
- 实现仓位 UI、绑定状态和立即出发校验。
- 记录到位等待后续方案。
- Debug 构建通过。
- `progress.md` 追加本轮记录并包含回滚方式。

## Out of Scope

- 本轮不实现到位 HTTP 上报。
- 本轮不实现每点五分钟等待。
- 本轮不实现超时继续下一点或最后一点自动召回。
- 本轮不把仓位绑定上传给上游。
- 本轮不持久化仓位绑定。

## Technical Notes

- 主要涉及 `MainActivity.java`、`activity_main.xml`、点位适配器或新增的仓位展示组件。
- 应复用当前 `DestModel.DataBean`，不复制一套点位结构。
- 需要以仓位绑定状态作为屏幕导航路线的唯一数据源，避免 UI 与导航数据不一致。
