# 增加上游地址设置

## Goal

在主界面增加“上游地址”设置入口，让现场人员直接修改上游服务器 IP `192.168.112.194`，不需要改代码重新打包。保存后无需重启机器人或 App 即可生效。

## What I already know

代码中 `192.168.112.194` 目前有 4 处仍在运行的上游端点，全部共用同一个 IP，仅端口不同：

| 用途 | 地址 | 位置 |
| --- | --- | --- |
| 到位上报 | `http://192.168.112.194:9088/nav_arrive` | `MainActivity.java:154` |
| 仓库任务 | `ws://192.168.112.194:9098` | `MainActivity.java:159` |
| 配送语音 | `http://192.168.112.194:9089/delivery.wav` | `MainActivity.java:170` |
| 状态上报 | `ws://192.168.112.194:9096` | `WebSocketService.java:32` |

生效方式已确认：

* `nav_arrive` 每次上报时新建 Request，读取即生效。
* 仓库任务每次发送时新建 WebSocket，读取即生效。
* 配送语音每次到位播放时读取地址，读取即生效。
* 状态上报是 `WebSocketService.onCreate()` 建立的长连接，需要主动 `close()` + `open()` 重连才能切换到新地址；该类已有这两个方法。

以下地址是历史遗留，当前不会连接，不纳入本次设置：

* `MyMultiCameraFragment2` 的 `9090-9093` 摄像头推流：`initFragmentLayout()` 在 `MainActivity.java:375` 已注释，Fragment 未加载。
* `MainActivity.initWebSocketManager()` 中的 `192.168.78.19:9096`：方法无调用点。
* `WebSocketService.WS2` 的 `192.168.108.19:9094`：`connect2()` 无调用点。
* `MyMultiCameraFragment` 的 `192.168.112.161`：旧版 Fragment，未使用。

机器人本机地址不是上游，不纳入设置：本机 HTTP 服务 `9095`、取餐回调 `192.168.112.89:9088`。

## Assumptions

* 4 个上游端点始终部署在同一台服务器上，因此界面只需要一个 IP 输入框，端口保持代码内固定。
* 现场只需要填写 IPv4 地址，不需要域名或带端口的完整 URL。
* 已保存的地址在升级后保留，不被默认值静默覆盖。

## Requirements

* 在主界面右侧增加“上游地址”按钮，并显示当前生效的 IP。
* 点击后弹出设置框，展示当前 IP、受影响的端口清单，并允许输入新 IP。
* 校验 IPv4 格式，拒绝空值、格式错误和超出 `0-255` 的段位，并给出明确提示。
* 保存后立即刷新按钮显示。
* 保存后 4 个上游端点全部使用新 IP，不需要重启机器人或 App。
* 保存后主动重连状态上报 WebSocket，使长连接切换到新地址。
* 提供“恢复默认”入口，可回到 `192.168.112.194`。
* 不修改导航、回充、仓位绑定、运行速度和取餐等既有业务行为。

## Acceptance Criteria

* [ ] 没有保存过地址时，界面显示 `192.168.112.194`，4 个端点均使用该 IP。
* [ ] 右侧显示“上游地址”入口，并能看到当前 IP。
* [ ] 输入合法 IPv4 保存后，按钮立即显示新 IP。
* [ ] 保存后触发到位上报、仓库任务和配送语音，均使用新 IP，无需重启。
* [ ] 保存后状态上报 WebSocket 重连到新 IP。
* [ ] 输入空值、`abc`、`192.168.1`、`192.168.1.256` 时不能保存，并显示校验提示。
* [ ] 点击“恢复默认”后恢复为 `192.168.112.194` 并立即生效。
* [ ] `:app:testDebugUnitTest` 和 `:app:assembleDebug` 通过。

## Definition of Done

* IP 配置的读取、校验、持久化和 URL 拼装集中在一处，没有散落的硬编码地址。
* 针对 IPv4 校验和 URL 拼装补充单元测试。
* Lint、单元测试和 Debug 构建通过。
* README 和现场文档说明可配置地址、受影响端口和生效时机。
* 进度日志记录改动文件、验证结果和回滚方式。

## Out of Scope

* 不把端口、机器人 ID、任务 ID 或本机服务端口做成可配置。
* 不清理上面列出的遗留地址和未使用的 Fragment。
* 不支持域名、多台上游服务器或按端点分别配置 IP。
* 不新增地址连通性探测或自动回退。
* 不处理仓库中既有的换行符差异文件和现场日志。

## Technical Notes

* 新增 `UpstreamServerConfig`，集中默认 IP、端口常量、IPv4 校验和 4 个 URL 的拼装；纯逻辑部分保持可单元测试。
* `MainActivity` 的 3 个常量改为按需从配置读取；`WebSocketService` 连接时读取配置，并新增重连入口供保存后调用。
* 复用现有 `MmkvUtils` 持久化和 `AlertDialog` + `EditText` 设置弹窗模式，与“运行速度”入口保持一致。
