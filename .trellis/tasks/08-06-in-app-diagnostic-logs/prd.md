# 应用内诊断日志窗口

## Goal

在不先修改机器人导航和回充控制逻辑的前提下，为主界面增加可现场操作的诊断日志入口。机器人出现“出发后几秒停止”或“回充后再次出发不移动”后，现场人员可以直接查看从 App 启动以来的关键业务时间线，并一键复制或将点击导出时的精确快照保存为 TXT 文件用于分析。

## What I already know

- 当前问题需要区分 SDK 提前回调 `STATE_DESTINATION`、回充任务抢占、PeanutCharger 未释放控制权，以及导航准备后未进入 `STATE_RUNNING` 等路径。
- 当前 `MainActivity` 中存在大量分散的 `Log.d/i/w/e`，但普通 Android App 无法在所有目标系统上可靠读取完整系统 Logcat。
- 右侧已有配送、机器人和屏幕操作分组，以及仓库任务状态区域。
- 项目已有 `AlertDialog` 使用方式，可以复用现有 UI 技术，不需要增加第三方依赖。
- Android 已提供系统剪贴板 API，可实现一键复制。

## Assumptions (temporary)

- 第一版优先记录导航、回充、上游 HTTP、仓库任务、到位等待和 Activity 生命周期等与当前故障有关的业务事件。
- 使用 App 私有目录中的轮转日志文件，并保留有容量上限的内存快照，避免日志无限增长影响机器人运行。
- 日志窗口只负责诊断，不提供导航、停止或重试按钮，不改变机器人控制行为。

## Open Questions

- 无。当前 MVP 范围已确认。

## Requirements (evolving)

- 右侧增加“运行日志”入口，点击后弹出可滚动日志窗口。
- 日志按时间顺序显示，至少包含时间、级别、模块和消息。
- 弹窗操作顺序为“刷新”“复制全部”“导出文件”“清空”“关闭”，保留既有刷新、清空和关闭语义。
- 弹窗打开时加载当前快照，并提供“刷新”按钮手动读取最新日志；不做定时自动刷新。
- 复制成功或日志为空时提供明确提示。
- 点击“导出文件”时立即捕获不可变的 `DiagnosticLogRecorder.snapshot()`；导出内容必须与该字符串的 UTF-8 字节精确一致，不添加 header、尾换行或 Logcat 内容。
- 空快照只提示，不创建文件；文件名使用 `robot-runtime-yyyyMMdd-HHmmss-SSS.txt`，成功后提示现场可见路径。
- Android 10/API 29 及以上通过 `MediaStore.Downloads` 写入 `Download/PeanutRobotLogs/`，设置 `RELATIVE_PATH` 并用 `IS_PENDING` 完成后安全发布，不申请存储权限。
- Android 9/API 28 及以下写入系统公开下载目录下的 `PeanutRobotLogs/`；仅在用户点击导出且缺少权限时，用独立 request code 申请 `WRITE_EXTERNAL_STORAGE`，授权后仍导出点击时保留的快照，拒绝后清理 pending snapshot 并提示。
- 导出磁盘 I/O 使用最多 4 个等待任务的有界单线程队列；队列饱和不得阻塞主线程。导出期间禁用按钮，完成、失败或调度被拒绝后恢复；权限弹窗期间即使原日志弹窗关闭也继续完成导出。
- 导出需捕获 `IOException`、`RuntimeException` 和 `SecurityException`，失败时清理 MediaStore pending 条目或旧系统半成品并回调结果。
- 日志必须跨 App 重启保留，并写入 App 私有目录，不能依赖外部存储权限。
- 日志文件和内存缓冲区必须有固定容量；超出后轮转或丢弃最旧记录，不允许无限占用存储或内存。
- 多线程产生的日志必须安全写入，界面读取时使用不可变快照。
- 第一版必须覆盖导航任务创建、路线准备、`STATE_RUNNING`、`STATE_DESTINATION`、导航停止/失效、回充开始/停止/状态、上游任务、到位等待和错误路径。
- 诊断日志继续同步写入 Android Logcat，便于开发人员使用 adb 对照。
- 不记录 SDK secret、密码或其他认证信息；复制内容可能包含点位名称、任务状态和局域网请求路径。

## Acceptance Criteria (evolving)

- [x] 点击右侧“运行日志”能够打开可滚动弹窗。
- [x] 从 App 启动到弹窗打开前的关键导航和回充事件可见。
- [x] 新日志产生后重新打开或刷新弹窗能看到最新内容。
- [x] App 重启后仍能查看重启前保留范围内的诊断日志。
- [x] “复制全部”将当前完整诊断快照写入系统剪贴板。
- [x] “导出文件”捕获点击时快照，空日志不创建文件，后台任务期间禁用按钮并在主线程提示结果。
- [x] API 29+ 使用 `MediaStore.Downloads`、`Download/PeanutRobotLogs` 和 `IS_PENDING`，不触发存储权限申请。
- [x] API 28 及以下仅在手动导出时用独立 request code 申请写权限，授权后导出保留快照，拒绝后清理 pending snapshot 且不进入 `startRobotCore()` 回调。
- [x] 纯 JVM 测试证明 Unicode、普通和空字符串 UTF-8 写入行为，以及文件名格式；写入不增加任何字节。
- [x] “清空”同时清除内存和本地日志文件，但不改变机器人任务。
- [x] 日志容量达到上限后 App 不崩溃，最旧记录被淘汰。
- [x] 从多个回调线程同时记录日志时不出现并发异常。
- [x] 日志窗口和记录动作不改变导航、回充、到位等待或上游协议。
- [x] 单元测试和 Debug 构建通过。
- [ ] 在目标设备完成“立即出发到停止”的日志采集与复制验收。
- [ ] 在目标机器人分别验证 API 版本对应导出路径、实际文件字节、权限授权/拒绝提示和系统下载应用可见性。

## Feasible Approaches

### Approach A: App 内部诊断日志缓冲区（推荐）

- 新增轻量级线程安全诊断记录器，关键业务路径主动写入。
- 优点：不依赖系统 Logcat 权限，目标机器人表现可控，字段和容量可测试。
- 缺点：只能看到接入记录器后的 App 业务事件，看不到系统和 SDK 内部未暴露日志。

### Approach B: 弹窗执行 `logcat -d`

- 尝试读取当前进程或系统 Logcat 并显示。
- 优点：理论上可以复用已有 `Log.*` 输出。
- 缺点：受 Android 版本、厂商系统、UID 和 `READ_LOGS` 权限限制，目标机器人上不可靠，不适合作为唯一方案。

### Approach C: 内部缓冲区加本地文件

- 在 Approach A 基础上同步写文件，支持重启后查看。
- 优点：可保留跨重启证据。
- 缺点：需要文件轮转、容量清理、隐私和读写失败处理，第一版成本更高。

## Confirmed Decisions

- 暂不修改导航和回充控制逻辑，先增加可复制的现场诊断能力。
- 不依赖读取完整系统 Logcat；以 App 自己的诊断时间线作为可靠数据源。
- “全部日志”定义为当前故障相关的完整业务时间线，覆盖导航、回充、HTTP、任务状态和到位等待，不替换 App 中所有现有 `Log.*` 输出。
- 日志需要写入 App 私有目录并跨重启保留，必须通过容量轮转控制存储占用。
- 日志弹窗采用打开时快照和手动刷新，不进行每秒自动刷新。
- 手动导出是诊断快照的第二种交付方式；它只消费点击时的现有 recorder snapshot，不扩大日志来源，也不把系统 Logcat 合并进文件。
- 共享下载目录按系统版本分流：API 29+ 使用 MediaStore pending 发布，API 28 及以下使用公开 Downloads 文件 API 和按需写权限。
- 导出使用独立的有界单线程执行器，不复用记录器的持久化队列，避免导出压力改变实时诊断记录保留行为。
- “运行日志”入口放入右侧屏幕操作分组，保持现有卡片样式，不替换其他业务按钮。
- 诊断弹窗不得成为新的机器人任务控制入口。

## Definition of Done

- 诊断日志入口、缓冲区、弹窗和复制功能完成。
- 手动导出、版本化共享存储、按需旧版权限流程、半成品清理和结果提示完成。
- 当前故障相关关键路径已接入诊断记录。
- 完成并发、容量、文本快照、精确 UTF-8 写入和文件名格式测试。
- 完成 Trellis 校验、相关新旧日志单元测试、Debug 构建和 whitespace 检查；项目既有 lint 错误不在本扩展范围内。
- 更新使用文档和 `progress.md`，提供明确回滚方式。
- 目标机器人上的日志采集、复制和导出验收继续保留为未完成项，任务不归档。

## Out of Scope

- 本任务不修复导航几秒停止或回充后不移动。
- 不读取其他应用或 Android 系统全部日志。
- 不增加远程日志上传、云端检索或后台管理。
- 不修改 Peanut SDK、HTTP、WebSocket、到位等待或回充协议。

## Technical Notes

- 预计涉及 `activity_main.xml`、`MainActivity.java`、新的诊断日志工具类及对应单元测试。
- 右侧操作区空间有限，入口应保持与现有操作卡片一致，并避免压缩“立即出发”等主要操作的触控高度。
- 日志窗口应使用可选择文本或只读文本视图，并通过 `ClipboardManager` 复制快照。
